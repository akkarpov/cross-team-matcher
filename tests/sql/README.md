# Проверки SQL-контракта

Перед запуском должен работать изолированный стенд `python scripts/local.py setup`.
Тесты подключаются к адресам из закрытого `.local/config.json`; приложение и рабочий доставщик по-прежнему используют один DSN каждый.

```powershell
$env:MATCHER_SQL_TESTS = '1'
python -m pytest tests/sql -q --tb=short
```

| Требование | Проверка |
|---|---|
| Т01 | Чужой сотрудник и менеджер не могут отвечать за адресата; remote transport не принимает LOCAL-согласие |
| Т02, Т17 | Неизвестный обязательный навык исключает всех; OWN_FIRST/OWN_ONLY/ALL применяются к подходящим строкам |
| Т03 | Выходные без рабочего дня отклоняются, периоды capacity не пересекаются, отсутствие исключает подтверждение |
| Т04 | Приглашение и отказ не создают назначений |
| Т05 | Два параллельных REPEATABLE READ принятия на 30 часов при бюджете 40: одно подтверждение; serialization retry сохраняет command_id |
| Т06 | Отмена, доставленная до оферты, оставляет терминальную отметку; teardown проверяет подтверждаемую отмену проектов |
| Т07 | Замена 30→40 часов требует нового согласия; действующие часы до согласия остаются 30, после — 40 |
| Т08 | Отзыв требует полученного подтверждения COMPLETED; дубликат и старая версия отклоняются, событие содержит до/после |
| Т13 | Повтор команды возвращает ту же квитанцию; тот же UUID с другим содержимым отклоняется |
| Закрытые данные | Личные поля удаляются из локальной квитанции; другая региональная transport-роль не читает LOCAL-команды; RLS закрытой карточки исключает менеджера |
| Позднее завершение | COMPLETE после отмены получает терминальную квитанцию и текущее состояние; очередь сходится, отмененное участие не становится COMPLETED |

Фикстуры используют новые UUID и префикс `test.<run-id>`. После успешного набора их проекты отменяются через штатный протокол, сотрудники и учетные записи деактивируются. История сохраняется. Набор не удаляет данные и не изменяет демонстрационные учетные записи.

SQL и распределенные отказные тесты выполняются последовательно: tests/stand временно выключает узлы. Не запускайте функциональный набор одновременно с остановкой узлов.

В функциональных фикстурах ожидание установления соединения составляет 15 секунд, чтобы восстановление отдельной тестовой БД на том же диске не подменяло проверку бизнес-правил. Прикладные тайм-ауты не изменены; время ответа при отказах проверяет отдельный набор tests/stand.
