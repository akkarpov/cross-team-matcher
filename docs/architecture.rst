Архитектура и модель данных
====================================================================================================

Три узла и два договора чтения
----------------------------------------------------------------------------------------------------

.. image:: diagrams/architecture.svg
   :alt: Три приложения и направления обмена PostgreSQL

::

   app C  ── один DSN ── PostgreSQL C  ── cat ──► R1, R2
   app R1 ── один DSN ── PostgreSQL R1 ── working ──► R2, C
   app R2 ── один DSN ── PostgreSQL R2 ── working ──► R1, C

``global`` — одинаковые секционированные отношения на всех узлах. Основные
строки принадлежат одному региону; PostgreSQL выбирает локальную или внешнюю
секцию по ``owner_region``. Метаданные SERVER и USER MAPPING создаются только
установщиком. Приложение не содержит списка адресов регионов.

``search`` читает только локальные основные строки и асинхронные копии.
``analytics`` на C агрегирует такие же копии без обращения к живым регионам.
``private`` хранит локальные контакты, аккаунты, роли и исходящую очередь.
Квитанции имеют глобальную оболочку для доставки, но не публикуются.

``postgres_fdw`` не даёт 2PC, автоматического переключения внешней секции на
реплику или глобальных FK/UNIQUE. Эти ограничения сохранены в архитектуре.
Родители с внешними секциями не имеют обещания глобальной уникальности;
физические владельцы используют составные ключи и CHECK региона.

Календарь и согласованность
----------------------------------------------------------------------------------------------------

Интервалы дат включают обе границы. Рабочие дни — понедельник–пятница, без
национальных праздников. Недельные часы равномерно распределены на пять дней.
Подходящим считается сотрудник, у которого хватает часов на каждый рабочий
день, а не только в среднем. ``ACTIVE`` и ``CONFLICT`` занимают часы.

Каждая мутация календаря обновляет ``employees.schedule_version`` до проверки
нагрузки. Конкурирующая транзакция с устаревшим снимком отклоняется и полностью
повторяется. Это предотвращает два согласия на одни последние часы.
Замена условий исключает старое назначение из проверки новой нагрузки.

Безопасность
----------------------------------------------------------------------------------------------------

Пароли хешируются PBKDF2-HMAC-SHA256 с индивидуальной солью и 600000 итераций.
Сессии подписаны, ограничены восемью часами и разделены по экземплярам.
Мутации защищены CSRF; личность берётся из сессии, а SQL повторно проверяет
локальные роли. Учётные записи и контакты не реплицируются. Физические таблицы
недоступны приложению для прямой записи. Рабочий пользователь не является
суперпользователем; доставщик имеет отдельную ограниченную роль.

Для сетевого размещения обязательны HTTPS и TLS PostgreSQL, настройка Secure
cookies и закрытые порты БД. Локальный учебный стенд слушает только loopback.
