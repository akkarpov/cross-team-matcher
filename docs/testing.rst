Испытания и критерии приёмки
====================================================================================================

Запуск
----------------------------------------------------------------------------------------------------

.. code-block:: powershell

   python -m pytest tests/test_auth.py tests/test_architecture.py tests/test_freshness.py -q
   python -m pytest tests/sql -q
   python -m pytest tests/stand -q
   python scripts/browser_check.py
   python scripts/build_docs.py

SQL и распределённые проверки требуют подготовленного трёхузлового стенда
и могут создавать синтетические тестовые записи. Отказные проверки кратко
отключают только узлы из ``.local/config.json`` и восстанавливают их.

Матрица ТЗ
----------------------------------------------------------------------------------------------------

.. list-table:: Что должно быть доказано
   :header-rows: 1

   * - Проверка
     - Критерий
   * - T01
     - Запрет чужой личности, региона, проекта и согласия за сотрудника
   * - T02
     - Все компетенции обязательны, неизвестное не считается подтверждённым
   * - T03
     - Границы дат, неполная неделя, отсутствия и пересекающиеся назначения
   * - T04
     - До согласия и после отказа доступность не уменьшается
   * - T05
     - Параллельные согласия не превышают календарный бюджет
   * - T06
     - Согласие/отмена, перестановка сообщений, история и удержание позиции
   * - T07
     - Новые условия требуют согласия, замена без двойного списания часов
   * - T08
     - Отзыв только после квитанции завершения; уникальность, версии и история
   * - T09
     - EXPLAIN показывает внешнюю секцию; DML изменяет владельца
   * - T10
     - Асинхронная доставка профиля/отзыва; запрет записи в копии
   * - T11
     - При выключенном C регионы продолжают местную и прямую работу
   * - T12
     - Устаревшая копия читается; недоступный владелец не подтверждает запись
   * - T13
     - Повтор после потерянного ответа не создаёт дублей
   * - T14
     - Начальная синхронизация и повторное применение не запускают бизнес заново
   * - T15
     - Восстановление рабочих/закрытых записей, очереди и квитанций
   * - T16
     - 10 прогревов + минимум 100 измерений; цель p95 ≤ 3 секунды
   * - T17
     - Три режима, приоритет до пагинации, пустой свой регион

Статус конкретных запусков, число тестов, версии и измерения приводятся
в ``docs/protocol.md``. Наличие сценария само по себе не является успешным
прохождением. Цели: ответ об отказе до 10 секунд, доставка при исправной
связи до 10 секунд, восстановление подготовленного комплекта до 30 минут.
При произвольном сетевом разделении верхняя граница доставки не гарантируется.
