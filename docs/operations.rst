Команды и HTTP API
====================================================================================================

Формальный конверт и девять бизнес-ошибок находятся в
``contracts/operations.json`` и ``contracts/errors.json``. Поля мутаций
перечислены в ``contracts/db-api.md``. Эти файлы версионируются с SQL.

Имена семи бизнес-возможностей из организационного плана сопоставлены с
фактическим транспортом в ``transport_kinds``: ``OFFER``, ``CANCEL``,
``COMPLETE``, ``RESULT``. Это четыре служебных сообщения, а не полный список
пользовательских действий. Локальные действия сохраняются с префиксом
``LOCAL.``. Удалённая роль не может отправить локальное согласие сотрудника.
Точное написание транспортных типов в Google Docs не фиксировалось;
эта конкретизация отличается от предварительных имён в локальном HTML-плане.

Интерфейс приложения
----------------------------------------------------------------------------------------------------

``GET /api/me`` возвращает локальную сессию. Коллекции доступны в
``/api/dashboard``, ``/api/employees``, ``/api/projects``, ``/api/invitations``,
``/api/assignments``, ``/api/reviews``, ``/api/catalog``, ``/api/analytics``,
``/api/events``. Детали используют ``/{owner_region}/{uuid}``.

``GET /api/search`` принимает режим региона, UUID компетенций через запятую,
минимальный стаж в месяцах, даты, часы в неделю и страницу. Поиск конкретной
позиции принимает ``position_id`` и ``position_owner``. Все навыки обязательны.

``POST /api/actions/{action}`` принимает JSON и заголовок ``X-CSRF-Token``.
В JSON рекомендуется передавать стабильный ``command_id`` UUID, сохраняемый
при сетевом повторе. ``actor_id``, ``manager_id`` и ``author_id`` из браузера
отклоняются. Ответ ошибки: ``{"error":{"code":"...","message":"..."}}``.
Актуальная машиночитаемая схема: ``/openapi.json``.

Процесс
----------------------------------------------------------------------------------------------------

#. Менеджер фиксирует оферту и outbox на владельце проекта одной транзакцией.
#. Доставщик отдельно вставляет команду в ``global.processed_commands``.
   Внешняя секция выбирается СУБД. Обработчик владельца не обращается к чужим
   узлам и атомарно фиксирует бизнес-изменение и результат.
#. Отдельная транзакция помечает местный outbox доставленным.
#. Сотрудник принимает или отклоняет оферту на домашнем узле. Только принятие
   после проверки календаря создаёт назначение.
#. Ответная квитанция доходит до проекта. Позднее завершение участия
   подтверждается владельцем сотрудника перед открытием отзыва.

Доставка допускает повторы. Совпадение ID, источника, типа и хеша возвращает
сохранённый результат. Другой хеш — конфликт. Потеря ответа после удалённого
COMMIT не означает, что изменения не было. Просроченная аренда сообщения
возвращает его в обработку после падения доставщика.

Локальные ошибки доступа, некорректные входные данные и конфликты версии
откатывают транзакцию. Зафиксированный бизнес-отказ сохраняет квитанцию и
событие без частичного назначения.
