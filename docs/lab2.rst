Лабораторная работа 2: Git и Doxygen
====================================================================================================

Основание: ``ТРПО_Лаба2_2023.pdf``, задания на страницах 19 и 38.
Тема — инструментальные средства управления версиями и составления
проектной документации. Выполнили Карпов Арсений Кириллович,
Лебедев Матвей Олегович и Кречун Артём Васильевич.

Git
----------------------------------------------------------------------------------------------------

Выполните ``python scripts/lab2_git_demo.py``. Скрипт создаёт отдельные
локальный bare remote и два клона в ``.local/lab2-git/<дата>``. Для примера
используется явно учебная личность; исходный проект и его историю он не меняет.

Демонстрируются clone/pull/log, новая ветка, коммит, push в локальный remote,
конфликт слияния, ошибочное разрешение, падающий тест, отмена merge командой
``git revert -m 1``, исправление и переименование ветки, повторное слияние,
успешный тест и удаление ветки. Push на внешний хостинг не выполняется;
для защиты внешний репозиторий при необходимости подключается отдельно.

Протокол текущего запуска содержит реальные команды и коды возврата:
``docs/generated/git-transcript.txt``. Намеренно падающий тест подтверждает
обнаружение ошибки, а не дефект основного проекта.

Doxygen и Visual Studio
----------------------------------------------------------------------------------------------------

Основной проект имеет документированные ``Database`` и производный
``ActorDatabase``, методы, параметры, возвращаемые значения и поля.
Sphinx autodoc строит справочник непосредственно из Python-кода.

Для буквального выполнения примера ``.h/.cpp`` и наследования из PDF
добавлен самостоятельный ``labs/lab2``: ``Employee`` и ``RegionalEmployee``.
Откройте папку как CMake-проект в Visual Studio 2022 (C++ workload).
В репозитории находятся CMake-конфигурация и исполняемый пример с проверками;
запуск самой Visual Studio отдельно не утверждается без проверки в IDE.

.. code-block:: powershell

   g++ -std=c++17 labs/lab2/Employee.cpp labs/lab2/main.cpp -o .local/lab2-example.exe
   .\.local\lab2-example.exe
   python scripts/build_docs.py --schema --doxygen

``Doxyfile`` задаёт русский язык, UTF-8, рекурсивное чтение и HTML + RTF.
UTF-8 соответствует фактической кодировке исходников; Windows-1251 из
старого примера методички не применяется к UTF-8-файлам.
Результат: ``docs/_build/doxygen/html/index.html`` и
``docs/_build/doxygen/rtf/refman.rtf``. Основной сайт:
``docs/_build/html/index.html``.

Что показать на защите
----------------------------------------------------------------------------------------------------

#. Страницу проекта и ссылки на ``Employee.h`` / ``Employee.cpp``.
#. Краткое и подробное описание класса, свойств и функций.
#. Документированные входные параметры и возвращаемые значения.
#. Производный класс ``RegionalEmployee`` и отношение наследования.
#. Те же сведения в RTF, открытом в текстовом редакторе.
#. Изменение комментария, повторную сборку и обновлённую справку.
#. Реальный Git-граф и вывод тестов до и после исправления.

Сценарий защиты проекта
----------------------------------------------------------------------------------------------------

Начните с трёх окон узлов. Создайте позицию на R1, найдите сотрудника R2,
отправьте приглашение и покажите неизменную доступность до согласия.
Войдите сотрудником на R2, примите предложение, дождитесь квитанции на R1.
Покажите запрет второго назначения сверх бюджета, завершение и отзыв.
Затем покажите EXPLAIN внешней секции, состояние подписок, локальные
закрытые таблицы и зафиксированный протокол отказных испытаний.
