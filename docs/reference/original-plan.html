Правая стрелка рисунка склеена из двух каналов. Их нельзя делать одним. Запись в чужую основную строку — postgres_fdw, секция global.* по owner_region. Копия — логическая подписка, только чтение. Реплика не подтверждает назначение.

На рисунке в регионе написано «сотрудники». По ТЗ там же основные проекты, позиции, приглашения, назначения и отзывы своего владельца. private, accounts и outbox на рисунке нет — их нет и в публикациях. За эти локальные таблицы отвечает Лебедев, в чужой узел их не кладёт Карпов.

Контракт 4.1

Обычный SQL к global.* для своих и чужих основных строк. Поиск — только search.*. Межрегиональный процесс — команда, не адрес.

command_id uuid
kind text
source_region smallint
target_region smallint
actor_id uuid          -- из сессии экземпляра, не из браузера
payload_hash sha256
payload jsonb

Квитанция в processed_commands пишется той же транзакцией, что и бизнес-изменение. Повтор того же command_id с тем же source, kind и hash возвращает сохранённый result. Другой hash — command_conflict. Одной транзакцией нельзя менять свой outbox и данные чужого владельца: 2PC через postgres_fdw в PostgreSQL 17 нет.

Ошибки: forbidden, payload_invalid, owner_unavailable, stale_replica, command_conflict, capacity_exceeded, terms_mismatch, review_not_allowed, version_conflict. На испытании недоступный владелец сообщается до 10 секунд. Это критерий, не измеренный результат.

Файлы contracts/operations.json и contracts/errors.json — те же имена. Заморозка 7 октября. Версия 4.2 только с согласия троих.

Задачи ганта, подробно

01 · 6–7 октября · все · блокер

Заморозить контракт

Пока json не в main, Лебедев не называет команды по-своему, Кречун не рисует лишний экран выбора сервера.

Сделать: семь kind из контракта, девять кодов ошибок, запрет actor из браузера, запрет второго DSN. Карпов пишет файлы, двое ставят ревью в тот же день.

Готово, когда оба json совпадают с таблицей команд и ссылка на них есть в docs/operations.rst.

02 · 7–8 октября · Карпов

Три PostgreSQL и три приложения

Как на рисунке: app_r1 → pg_r1, app_c → pg_c, app_r2 → pg_r2. Отдельные тома и адреса. wal_level=logical. Пароли только в env, не в репозитории.

Файлы: deploy/compose.yml, deploy/.env.example, deploy/postgres/servers.sql. В образе приложения нет переменной с адресом чужого региона.

Готово, когда каждый экземпляр открывает только свой узел, а SERVER для чужой секции создан миграцией, не клиентом.

03 · 7–8 октября · Лебедев

Справочники, люди, календарь

Таблицы 1–7. global.employees PARTITION BY LIST (owner_region). На R1 своя секция r1_data.employees и внешняя route.employees_r2. employee_private не прикрепляется к global.

Файлы: sql/cat/01_regions_competencies.sql, sql/global/01_employees.sql, sql/global/02_attach_local.sql, sql/private/02_employee_private.sql, sql/working/01_calendar.sql. На каждую таблицу COMMENT ON.

Готово, когда интервалы одного сотрудника не пересекаются, а отсутствие периода означает отсутствие подтверждённой доступности.

04 · 7–8 октября · Кречун

Один код и один DSN

Оболочка, не копия Department Control Center. Светлая бумага, один медный акцент. Роли: сотрудник, редактор, менеджер, администратор каталога, аналитик. Регион экземпляра задаёт окружение, не пользователь.

Файлы: app/db.py, app/config.py, design/tokens.css, app/templates/base.html, app/templates/login.html. Тест падает, если в репозитории есть второй DSN или строка r1_data.

05 · 8–9 октября · Карпов · после 03

Потоки рисунка

C публикует только cat.regions и cat.competencies. R1 публикует свои r1_data рабочие таблицы в R2 и в C. R2 — симметрично. Копии, private, accounts и outbox в публикацию не входят. publish_via_partition_root остаётся false.

Файлы: replication/c_catalog.sql, replication/r1_working.sql, replication/r2_working.sql, replication/check_lag.sql.

Готово, когда навык с C доезжает до R2, а вставка в копию на R1 отклоняется правами.

06 · 8–9 октября · Лебедев

Проект, позиция, оферта

Таблицы 8–11. Статусы проекта: FORMING, READY, ACTIVE, CANCELLING, CANCELLED, COMPLETED. Позиций 1–10. Все компетенции обязательны. Одна открытая оферта держит позицию и не резервирует часы сотрудника.

Файлы: sql/working/02_projects.sql, sql/working/03_invitations.sql. terms_snapshot и terms_hash неизменны после отправки.

07 · 8–10 октября · Кречун

Экраны процесса

Каталог только у администратора C. Профиль и календарь — у редактора своего региона. Проект и поиск — у менеджера, приоритет своего региона до страницы. Входящие приглашения — у сотрудника, менеджер не нажимает «согласен» за него. Отзыв скрыт, пока нет квитанции завершения. Пустая выдача не маскирует недоступный узел.

Файлы: app/templates/catalog.html, profile.html, project.html, search.html, invite.html, review.html, analytics.html.

08 · 10–11 октября · Лебедев · после 06

Назначение, отзыв, команды

Таблицы 12–19. employees.schedule_version растёт на каждой мутации календаря. Два подтверждения на последние часы сериализуются на владельце сотрудника. CONFLICT не освобождает часы. Отзыв после COMPLETED, правка пишет workflow_events.

Файлы: sql/working/04_assignments.sql, sql/working/05_reviews.sql, sql/process/outbox.sql, sql/process/processed_commands.sql, sql/search/employee_profiles.sql, sql/analytics/reports.sql, tests/sql/test_capacity.sql, tests/sql/test_dedup.sql.

09 · 11–12 октября · Кречун · после 05 и 08

Стыковка с живым SQL

Те же шаблоны, уже против секций и команд. Приложение не выбирает хост: EXPLAIN на R1 для owner_region = 2 показывает внешнюю секцию. Баннер копии берёт время из search, не из выдуманной метки. Аналитик на C видит статус подписки.

10 · 12–14 октября · все

Отказы и протокол

Карпов гасит C и R2, снимает EXPLAIN, гоняет восстановление. Лебедев подтверждает, что дамп чужого узла не содержит private и хешей. Кречун проводит Т01–Т08 и Т17 с экрана. В docs/protocol.md только факты: версии, SQL, UUID, лаг, время. Пустые p95 не писать.

Файлы: tests/stand/test_explain_fdw.sh, test_c_down.sh, test_owner_down.sh, test_lost_response.sh, deploy/backup/backup.sh, deploy/backup/restore.sh, deploy/failover/promote_r1.sh.
