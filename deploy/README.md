# Запуск изолированного стенда

На Windows нужен PostgreSQL 17 (проверенная локальная версия — 17.4) и Python 3.11.
Все данные создаются в `.local`, системная служба PostgreSQL не используется.

```powershell
python -m pip install -r requirements.txt
python scripts/local.py init
python scripts/local.py db-start
python scripts/local.py setup
python scripts/local.py seed
python scripts/local.py start
```

Открыть C: `http://127.0.0.1:8100`, R1: `http://127.0.0.1:8101`, R2:
`http://127.0.0.1:8102`. Сгенерированные логины и пароли находятся в
`.local/demo-credentials.json`. SQL-порты — 55430, 55431, 55432. Данные вымышлены.
Скрипт `stop` останавливает только процессы этого проекта и его три кластера.
Повторный `setup` проверяет SHA-256 миграций, сохранённые в комментарии базы,
и не применяет исполненные файлы повторно. Для изменения установленной схемы
нужен следующий номер SQL-миграции.

```powershell
python scripts/local.py status
python scripts/local.py stop
```

## Docker Compose

Контейнерный вариант не требует локального PostgreSQL. Образы:
`postgres:17.4-bookworm`, `python:3.11.11-slim-bookworm`. Эти версии намеренно
зафиксированы для учебной воспроизводимости. Digest образов надо записывать
при фактическом скачивании; в поставке он не выдуман.

```powershell
python scripts/local.py compose-env
docker compose --env-file .local/compose.env -f deploy/compose.yaml up --build -d
```

Адреса контейнерных приложений: `http://127.0.0.1:8200`, `:8201`, `:8202`.
Bootstrap создаёт роли, БД, схему, FDW, 6 подписок и демонстрационные данные;
приложения стартуют после успешного bootstrap. Секреты монтируются из `.local`.
Тома БД независимы. Команда `down` сохраняет тома; `down -v` удаляет данные и
для обычной остановки не нужна. Docker в исходном Windows-окружении отсутствовал,
поэтому фактический протокол относится к нативному стенду.

## Проверки и восстановление

Распределённые тесты действительно выключают центральный и региональный узлы.
Их запускают последовательно после функциональных SQL-тестов, без приложений
и фоновых worker-процессов:

```powershell
python scripts/local.py stop
python scripts/local.py db-start
$env:MATCHER_SQL_TESTS = '1'
python -m pytest tests/sql -v
$env:MATCHER_STAND_TESTS = '1'
python -m pytest tests/stand -v
```

Факты и исходные замеры сохраняются в `.local/test-results/distributed-facts.json`.
T16 делает 10 прогревов, затем 100 измерений с пятью параллельными пользователями.
Время включает подключение и транзакцию, а не только SQL EXPLAIN.

```powershell
python scripts/local.py backup
python scripts/local.py restore --backup .local/backups/ИМЯ_КОПИИ
```

`backup` останавливает приложения, сравнивает все опубликованные наборы строк
между узлами, сохраняет каждый узел отдельно и записывает число/хеш строк всех
локальных таблиц. Сюда входят private, outbox и квитанции. Подписки не попадают
в архив: их восстанавливают по topology. Для учебной проверки `restore` создаёт
новые БД `matcher_restore_*`, восстанавливает архивы, сравнивает все контрольные
значения и устанавливает read-only. Основные БД остаются на месте. Приложения
после backup надо запустить явно. Архивы содержат закрытые сведения и секреты
USER MAPPING, поэтому `.local` не публикуется и не помещается в Git.

Для аварийного восстановления основных владельцев требуются остановка записи,
проверка резервных копий и пересоздание подписчиков из проверенных владельцев;
автоматическое переключение копий не реализовано и не заявляется.
