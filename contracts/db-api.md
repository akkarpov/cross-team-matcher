# Database contract

PostgreSQL 17. Application connects once per node as `matcher_app`. The owner region is `SELECT private.node_region()` (0 = C, 1 = R1, 2 = R2); actor comes from a validated local account, never request form fields. In each authenticated transaction run `SELECT set_config('app.actor_id', %s, true)`.

Authentication: local `private.accounts(account_id uuid, owner_region smallint, employee_id uuid NULL, login text, password_hash text, active bool)`; `private.account_roles(account_id, role_code, scope_id text)`. Roles: `EMPLOYEE`, `EDITOR`, `MANAGER`, `CATALOG_ADMIN`, `ANALYST`. Scope is `*`, region number, or project UUID. Password hashes use the backend's chosen format; demo seed is generated by the deployment initializer.

Mutation: `SELECT global.mutate(action text, payload jsonb)`. Every payload SHOULD contain UUID `command_id`; database creates one when omitted. Same command ID and content returns original JSON result; changed content is rejected. Results are `{ok:true,...}` or `{ok:false,error:...,message:...}` for business failures. A failed acceptance uses public `capacity_exceeded` or `payload_invalid` (missing requirements); its receipt and audit event must commit. SQL permission/validation/version errors abort the transaction. All mutation inputs use snake_case below. IDs and ownership cannot be changed. `owner_region` is derived from account/node; response actions must use the employee's home node.

Read schemas: `cat.regions`, `cat.competencies` are local catalogs. `global` relations have their specification fields plus `updated_at`; invitations additionally expose `assignment_id`, `assignment_status`, `replaces_invitation_id`, `version`, `created_at`; positions have `version`; assignments expose `project_region`, `project_id`, `position_id`, `terms_version`; invitation_responses expose `position_id`, `project_id`, `assignment_id`, `source_version`.

`search.employee_profiles` contains employee fields plus `source_region`, `source_updated_at`, `is_local`. `search.employee_competencies`, `capacity_periods`, `unavailability_periods`, `assignments`, `projects`, `project_positions`, `position_competencies`, `invitations`, `invitation_responses`, `workflow_events`, `reviews` read only local originals/copies. Global queries against unavailable foreign owners can fail; search never contacts them.

`search.candidates(position_owner smallint, position_uuid uuid, mode text DEFAULT NULL, page integer DEFAULT 1)` returns `{items:[employee + available_hours_per_week + competencies],total,page,page_size:25,mode,own_region}`. Active catalog, all requirements, experience, every working day and requested hours are checked before region ordering. `search.freshness()` returns subscription/table readiness and last replication receipt times; no fabricated lag guarantee.

Worker uses the same local database as `matcher_worker`: select eligible `private.outbox`, deliver INSERT to `global.processed_commands(owner_region,command_id,source_region,actor_id,kind,payload_hash,payload)` in its own transaction; on unique violation read existing receipt and compare source/kind/hash; then mark local outbox DELIVERED in a separate transaction. Failure increments attempts and sets next_attempt_at. `SELECT private.command_hash(payload)` uses canonical JSONB SHA256. `processed_commands` AFTER INSERT trigger applies owner-local business mutations atomically and stores result. INSERT RETURNING does not contain the later result update; read the receipt after INSERT. Do not combine foreign delivery and outbox updates in one transaction.

Seed and topology are separate from schema, so operational installation can rerun without inserting demo identities. `sql/00_schema.sql` takes psql variable `node_region`, creates compatible replica tables everywhere and publications on their actual owners. `replication/bootstrap.py` installs FDW and foreign partitions after all sources exist. Catalog and working logical subscriptions are created by deployment bootstrap, outside transactions.

`search.find_candidates(first_day date,last_day date,requested_hours numeric,required_competencies uuid[],minimum_experience integer,region_mode text,page_number integer DEFAULT 1,query_text text DEFAULT '')` supports a general search before selecting a position. `search.remaining_hours(owner smallint,employee uuid,first_day date,last_day date)` returns the minimum remaining daily budget multiplied by five, preserving fractional hours. Source dates describe changes to a row; transport freshness is separately reported by `search.freshness()` as `{node_region,checked_at,sources:[{source_region,subscription_name,enabled,ready,last_received_at,last_message_at,latest_end_time}]}`.

Private profile SELECT is protected by PostgreSQL RLS: the employee sees their own local card, and an EDITOR sees cards in their authorized home region. Application reads additionally scope every user-facing query by the authenticated roles and account. Password hashes are readable only by the trusted backend database role for local login; they are never returned in user-facing JSON.

Receipt privacy: regional transport logins can read only their own incoming service-command receipts. `LOCAL.*` receipts are unavailable across FDW. Closed profile fields are consumed locally and removed from the saved local command payload; `payload_hash` retains the original input digest to verify exact retries, so it intentionally is not the digest of the redacted saved payload. None of the receipt tables are in logical publications.
